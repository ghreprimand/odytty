## 2026-09-06 -- Named profiles: launch context now takes effect

A round of hands-on profile testing found the profile editor was solid but a
launched profile did not do what it advertised. Several launch-path defects are
fixed together:

- Environment overrides were dropped for the common case. A profile that set
  environment variables but no shell or command launched with none of them: the
  default-shell spawn path ignored the resolved environment map. Both PTY
  backends now accept the profile environment on the default-shell spawn and
  apply it after the standard interactive-shell setup, so a profile value wins
  over a discovery advertisement, matching the explicit-shell path. On Unix the
  overrides pass through fork/exec; on Windows they fold into the ConPTY
  environment block, the same route TERM_PROGRAM already takes.
- A non-existent starting directory no longer dead-ends a tab. The editor now
  rejects a starting directory the user types or changes that does not exist,
  naming the path, while a directory loaded unchanged from an existing profile
  is preserved even if it is momentarily absent (removable media, an unmounted
  share). At launch, a resolved profile directory that no longer exists falls
  back to home with a bounded notice instead of failing the spawn, on the new
  tab and restore paths alike. Cross-platform: the home fallback is `$HOME` on
  Unix and `%USERPROFILE%` on Windows.
- Deleting or renaming the global default profile keeps the saved default
  coherent. Deleting the profile named as the global default clears the
  `default_launch_profile` key so the next New Tab opens a plain System Default
  tab rather than resolving a missing default; the manager states the default is
  now System Default. Renaming the default rewrites the key to the new name. A
  workspace-scoped launch-profile override that names the deleted profile is
  cleared, and rewritten on rename, so a stale binding cannot outlive the
  profile.
- A profile theme is now visible and durable. The theme a profile selects is
  carried as per-session state, so a global theme sweep (a settings write, an
  OS dark/light flip, a restore seed) re-derives every session's colors
  individually and never flattens a profile tab to the global theme. While a
  profile tab is active the window chrome and GPU present that theme, switching
  back to the global theme on a tab or workspace switch to a plain pane. Colour
  vision adaptation still applies on top. This also resolves a report that
  turning Follow OS theme on then off left a profile tab showing the wrong
  colors: that was the sweep flattening the tab, not a following bug.

Editor ergonomics improved alongside the launch fixes:

- The Theme row cycles the sorted built-in roster plus any user theme files with
  Left/Right, the same way the Shell row cycles discovered shells, and typing a
  name still works. Save rejects an unknown theme name with an inline error
  instead of silently falling back at launch. The roster loads on demand when
  the form opens and never touches the startup path.
- The profile form scrolls under the mouse wheel without moving field focus, and
  the catalog scrolls too; the form shows the same scroll indicator the catalog
  does when more rows sit below the view.
- The catalog filter is started with `/` so the single-key hotkeys
  (d/r/g/x/i/e) no longer steal the first character of a profile name being
  typed as a filter. While filtering, every printable character reaches the
  query; the hotkeys act only with an empty, inactive filter.

Windows behavior is stated per change: environment overrides cross ConPTY, the
home fallback uses `%USERPROFILE%`, and the theme and editor changes are
platform-neutral. Regression coverage spans an end-to-end env-only spawn, the
missing-directory fallback, workspace-binding clear and rename, the profile
theme surviving the sweeps and driving the chrome across a Follow OS toggle, the
theme roster and unknown-name rejection, the wheel scroll, and the `/` filter.

## 2026-09-06 -- Profile editor repaints on every keystroke

Typing into the profile editor's newer fields (command program and arguments,
environment key and value rows, font, font size, saved layout, switch-rule
hosts and directories) and toggling the tri-state and cycle fields produced no
visible change until the focus moved: the manager's repaint change-detection
signature enumerated the original eleven draft fields and was never extended
when the editor grew to cover the whole schema. The signature is now derived
from the same rendered form lines the painter draws, so any field that renders
is covered automatically and a future field cannot be missed. The catalog
signature also gained the Add-row focus, the default marker, display names,
and the first warning, which were likewise absent. Regression tests iterate the
live field list and assert that every edit changes the signature, and pin the
reported case (Enter on the Add environment row, then typing into the new key
row). Sibling check: the connection form signature lists every one of its
fields; the older pickers have a signature matrix test already.

## 2026-09-05 -- Roadmap: keyboard-first window merge planned for v0.15.0

The roadmap and TODO now record a planned v0.15.0 window-merge capability:
`Merge this window into...` and `Pull window ... into this one` from the
command palette and Session Navigator, with a target picker that lists the
other windows by tab count, active title, and directory and paints a large
temporary numeral inside each candidate window while it is open. The numeral
approach was chosen over drag-and-drop because Wayland exposes no window
positions or cross-window drop events to a client, and over title-bar
identification because tiling compositors such as Hyprland draw no title bars;
painting inside the terminal's own surface works on every platform without
compositor cooperation. Tabs keep their PTY, profile, and attach handle; a
failed merge leaves both windows unchanged. TODO.md also gained a v0.14.0
section recording the in-tree scope and the open acceptance and checkpoint
items, and the roadmap notes the shared overlay hit-test model shipping in
v0.14.0.

## 2026-09-05 -- Security and correctness hardening

Targeted hardening across input, clipboard, opener, session-host, and terminal
core paths:

- Bracketed-paste sanitizers in both the input encoder and the clipboard chunker
  now converge to a fixed point. A crafted payload that reassembles the paste-end
  marker after a deletion (`ESC[2` + `ESC[201~` + `01~`) previously left the exact
  marker it exists to remove; the scan now checks the growing output tail so a
  reassembled marker is stripped in the same linear pass.
- The "Open With" MIME sniff refuses non-regular files and opens with
  `O_NONBLOCK`, so a hostile program that names a FIFO can no longer wedge the UI
  thread waiting for a writer.
- Hover path resolution memoizes its filesystem probe per pointer cell and
  scrollback position, so the up-to-eight metadata probes no longer re-run on
  every reported pointer motion and a path under a stalled mount cannot repeatedly
  freeze input.
- Openable `file:` hyperlinks are restricted to local targets: a remote or UNC
  authority (`file://host/...`, `file:////server/share`) is rejected rather than
  handed to the OS opener, closing an SMB credential-leak and remote-execution
  path on a single click.
- Detach and switch routes the reported working directory through the shared
  spawn-cwd validator like every other spawn entry point.
- The memory-report diagnostic writes through the hardened, per-user state
  directory helpers instead of a fixed name in the shared temp root, and the
  desktop-notification spawn suppresses the console window on Windows like every
  other console child.
- The theme builder saves through the atomic-write path, so a crash mid-save can
  no longer leave a truncated theme file for the immediate re-read.
- Tab labels strip control characters and advance by display width, closing the
  one cell-grid writer that bypassed the universal control-character backstop.
- Insert and delete character (ICH/DCH) now sever the soft-wrap flag on every
  invocation, since both destroy the right edge; a later resize can no longer
  fuse a wrapped remnant with the row below.
- Tall Sixel images clamp their stored row extent to the screen from the cursor,
  matching the column clamp and the other image protocols.
- The attach client shares one poison flag across its input, resize, and detach
  paths: a truncated write on any of them (a desynced stream) now fails the others
  closed instead of writing further frames onto a corrupted stream, and the attach
  reader grows its frame buffer incrementally like the host reader rather than
  reserving the whole declared length up front.
- Text-selection copy, primary-selection copy, and copy-mode yank reconcile any
  pending scrollback trim before reading, so a copy issued in the window between
  a background output burst evicting history and the next repaint clears a
  now-stale selection rather than copying different, shifted rows.
- The active-prompt input and prompt-start anchors carry the scrollback trim
  epoch and fail closed when eviction has shifted every absolute row, so
  synthesized prompt-editing keystrokes can no longer target the wrong line.
- Sixel decoding gained a per-command painted-column budget, so a repeat-run
  flood that resets the cursor for free can no longer amplify decode work without
  bound; its pixel budget is now aligned to the image store's decoded-byte cap so
  an over-budget canvas is refused before it is allocated and zeroed.
- Inline iTerm2 images check the RGBA expansion against the decoded-byte cap
  before conversion, matching the Kitty path, so a single-channel image that just
  fits the native decode budget cannot expand to several times that on conversion.
- A Kitty image transmitted-and-displayed by number now tags its placement with
  the terminal-assigned id, so the client can delete or address what it drew using
  the id the terminal reported, and two numbered images no longer collide on a
  shared placement id.
- The per-terminal raw graphics-command ring, which copied and retained up to
  64 MiB of payloads that no code read, was removed; the validity gates it existed
  to compute are kept without the copy or the retention.
- Window focus loss now also clears the rename-field drag latch and the cached
  keyboard modifier state, so a drag or a held modifier interrupted by an
  alt-tab cannot resume as a phantom caret move or a phantom modifier on the next
  keypress; and the tab-bar grid recompute skips a zero-size window like the
  primary resize path, so a minimized or pre-configure window no longer forces a
  destructive 1x1 reflow.
- The Keybindings overlay's click-to-row mapping now honors the visible window
  bound, so a click on the panel border or below a scrolled list can no longer
  arm an off-window action. A configuration binding one chord to two actions is
  now surfaced: the chord resolves to a single action and the shadowed action
  shows as unbound, with a warning at load time.
- Workspace-rail context-menu actions re-validate the clicked slot against the
  workspace that was under the pointer at open time, so a background workspace
  closing and shifting the rail can no longer land a Close/Rename/Move on the
  wrong workspace. The font picker strips control characters before measuring, so
  a malformed font name cannot miscount the row width budget.
- Copy File on a Windows UNC path now produces a well-formed `file://host/share`
  URI (host as authority) instead of a four-slash malformed one. The child
  environment builder keeps its set and removed-variable lists disjoint so both
  PTY backends resolve a set-then-removed key identically. Emoji fontconfig
  discovery is gated to Unix-non-macOS like the symbol-font resolver, avoiding a
  console flash on Windows.
- Scrollback search caps its match count, so a broadly-matching query against a
  very large scrollback can no longer build an unbounded result on the UI thread.
  The fuzzy match scorer's inner transition is now an incremental running maximum,
  reducing its worst case from quadratic to linear in the candidate length with
  identical scores.
- The vs-background contrast-floor exemption table and the floor/re-check
  algorithm are now a single shared implementation used by theme generation, the
  colour-vision-deficiency adaptation pass, and the interactive theme author, so
  a future change to one can no longer silently diverge the three.
- The CI build/test workflow declares least-privilege read-only permissions, and
  the informational font-parser advisory exception regained its documented
  removal trigger and pre-expiry early-warning window without moving its date.
- Two confirmation dialogs were widened so their action lines render in full
  rather than clipping the trailing "Cancel", and a batch of stale source-comment
  and module-doc claims across the parser, graphics, font, logging, theme,
  settings, layout, context-menu, about, and native-entry modules were corrected
  to match shipped behavior.

## 2026-09-04 -- Profile editor schema coverage

Profile Manager now exposes the full profile schema through a sectioned,
scrollable editor grouped into Identity, Launch, Appearance, Cursor, Effects,
Layout, Switching, and Actions. Bounded command arguments, environment
overrides, and host/directory switch rules use explicit add, edit, and remove
rows with an inline message at the documented limit. Boolean overrides cycle
inherit/on/off and enumerations cycle only supported values; platform selection
uses local schema values without running a platform command. A hand-authored
multi-platform set is preserved intact when the chooser is left untouched, so an
unedited save reproduces the source document byte for byte. Every row, section
header, and Save/Cancel action carries its own pointer target and is reachable
by keyboard and mouse in every scroll state. The form editor was split into its
own module so both source files stay within the file-size limit; the earlier
duplicate command-program row and repeated section headers are gone. Text entry
was hardened: the space bar now types a literal space into every free-text field
and only cycles tri-state and enumerated fields; the word "inherit" is a
sentinel exclusively for those closed-vocabulary fields, so free-text scalars
and list entries (arguments, host and directory rules, environment values)
round-trip the literal word unchanged, and an unedited save still reproduces the
source document byte for byte. An environment override left with only a key or
only a value blocks the save with an inline error rather than being silently
dropped, while a row cleared on both sides is discarded as intended. The
delete-confirmation pointer split now reads the exact rendered button line so the
hit target cannot drift from the visible label.

## 2026-09-02 -- Unified session navigator

A Session Navigator replaces the Manage Sessions view. It opens through the
existing session shortcut, the command palette, and the context-menu entry,
and lists workspaces, tabs, panes, and Unix detached sessions in one
searchable overlay. The snapshot reads the live workspace arena and the
detached-session registry without polling, attaching, waking, or retaining
command output; up to 1024 rows are indexed and search reaches beyond the
display cap. Rows bound titles, directories, remote host identity (user and
port redacted), running/idle/exited/error state, OSC 9;4 progress, unread
activity, and launch profile.

Focus, attach, rename, duplicate, move, and close reuse the existing routes and
re-resolve their target by stable identifier at execution time, so a row that
vanishes or reorders between selection and action is a no-op. Live closes
require confirmation. Reopen starts a fresh shell from a bounded,
process-lifetime directory/profile descriptor (16 entries) and never resumes a
process; the attach-replace path is exempt because it turns a hosted tab back
into a registry session. Detached rows whose registry entry is stale or in an
error state show `session unavailable` and cannot be activated, while kill
remains available for cleanup.

An explicit `navigator_preview` setting (off by default) shows up to eight
lines from the last presented frame. Review found the initial redactor covered
only three keyword prefixes; it now fails closed on sensitive-key assignment
families (pass/pwd/secret/token/key/auth/bearer/credential/cookie/session)
across `export`, `set`, `$env:`, JSON, and YAML forms, on `Authorization` and
bare `Bearer` headers, URL credentials, private-key blocks, and any long
hex/base64 token, while keeping assignment keys visible and leaving ordinary
output such as `PATH=/usr/bin` untouched. Windows lists live panes but does not
claim detached-session support until a Windows detached session-host surface
exists. Gate: single-threaded full
suite green with an adversarial redaction corpus and refresh-race tests.

Follow-up: the Windows CI leg failed clippy because the detached-registry
append helper and its bounded-append test had no caller off Unix. Both are
now compiled only on Unix, matching the documented platform statement.

## 2026-09-01 -- Security review closure: targeted hardening

An external public security review reported 14 findings. Each was classified
against current code before any change: two true positives in shipped code
(remote paste temp-name entropy and non-exclusive remote create; installer
trust chain), several defense-in-depth items whose primary gate already
existed upstream, tooling-only items in non-shipping scripts, false positives
with regression evidence retained instead of rewrites (preregistration digest
comparison, active graphics-fuzz support module), and one informational
maintenance advisory. None was a release blocker, and no finding was closed
without a code citation and a test.

The configuration write boundaries now revalidate theme filenames at the
filesystem sink and reject control characters in every `hosts.conf` mutation
path without changing the original file on rejection. Remote image paste names
use operating-system cryptographic randomness and remote POSIX upload commands
use noclobber, so existing paths and symlinks fail instead of being followed.
The Windows client continues to use `ssh.exe` without a ControlPath; this does
not claim detached Windows-host support.

The release workflow now publishes a version-pinned installer asset inside the
signed `SHA256SUMS` manifest. The installer authenticates that manifest with
the pinned Minisign public key before accepting an artifact checksum and fails
closed when Minisign is absent, except for an explicit insecure opt-out whose
trust tradeoff is documented. Public documentation now places the pinned,
signature-first installation path ahead of mutable bootstrap commands.

Remote cleanup names only OdyTTY-minted `/tmp/odytty-paste-<hex>.png` paths;
anything else is dropped at the command boundary. An entropy seam lets tests
drive the fail-closed path. Tooling now precompiles bounded mutation batch
expressions, constrains internal compatibility-harness state filenames, and
limits public benchmark-anchor HTTP responses; none of these change valid
terminal behavior or frozen measurement semantics, so the benchmark protocol
version is unchanged and existing results are unaffected. On the test side,
external-palette read-count assertions now share a crate-wide lock so the
parallel CI suites cannot race them, directory switch patterns accept POSIX
roots on Windows (WSL and remote panes report POSIX directories), and the
auto-switch fixtures redirect APPDATA so the Windows leg reads the fixture
catalog. A follow-up aligned the Windows-only upload-command test with the
noclobber remote command; the sibling assertion is gated on `cfg(windows)` and
was invisible to the Linux gate. The `ttf-parser` maintenance advisory remains informational rather
than a disclosed vulnerability, retains its 2026-10-15 fail-closed expiry, and
requires parity evidence before any Fontations migration. Focused Rust and
Python checks pass; release-wide gates remain required before a release.

## 2026-09-01 -- v0.14.0 direct profile chooser, global default profile, and startup default

Profile selection is now a first-class launch surface instead of a palette-only
route. Plain `+`, New Tab, and New Workspace stay one-click and resolve the
effective default: the workspace `launch_profile` binding when set, otherwise
the new global `default_launch_profile` (`ODYTTY_DEFAULT_LAUNCH_PROFILE`), set
from Profile Manager with a visible **Set as Default** action (`g`) and a
`[default]` row marker. A chevron beside the tab-strip and workspace-rail `+`
and **New Tab / New Workspace with Profile** context-menu rows open a lazily
loaded, searchable profile picker; the catalog is read only when the picker
opens or a configured name must resolve. The first window follows the same
precedence: `--profile`, then the global default, then System Default. Missing
or invalid defaults fall back to System Default with a bounded warning and never
rewrite the saved value; explicit host or profile choices open a plain
placeholder workspace so the global default is never layered under them.
Review found the workspace-rail chooser hit region split at half the rail width
while the chevron is painted near the label column; the hit-test now splits at
the painted column on both axes with a regression test across narrow and wide
rails. Windows PowerShell/cmd/WSL discovery is reachable from the Profile
Manager shell field (Left/Right cycles cached suggestions; structured WSL rows
persist as a launch command), so no discovery code is production-dead on any
platform. Test isolation: env-redirecting and catalog-count-asserting tests
share crate-wide locks with a fixed acquisition order, closing the parallel
race behind the earlier Ubuntu failure. Gates: `cargo fmt --check`,
`cargo clippy --all-targets --locked -D warnings`, and
`cargo test --locked` at `RUST_TEST_THREADS=1` pass; production-file guard
and RustSec audit run in the same landing.

## 2026-09-01 -- v0.14.0 profile launch routing, restoration, and auto-switch

Named profiles route through new-tab, workspace binding, command palette, saved
layout open/restore, `--profile` CLI selection, and per-pane shape capture while
the ordinary default launch still avoids catalog enumeration and shell discovery.
Resolution merges launch fields through the existing precedence chain with a
distinct workspace `launch_profile` binding (separate from the shipped
`default_profile` SSH host alias). Local spawns and restored panes honor
profile shell, command, cwd, env, and appearance; profiles with a `connection`
alias route through the existing SSH connect path. Per-pane `launch_profile` is
captured into workspace shapes and replayed on launch restore and layout open.
Opt-in `profile_auto_switch` evaluates local match rules on focused-pane cwd
changes, applies appearance through the existing session seam, and shows a
short HUD naming the profile and match reason; remote panes use only the trusted
saved host identity for host rules. Cached read-only shell discovery covers
Windows PowerShell/cmd/WSL plus macOS/Linux login shells for pickers only.
Focused profile, launch, discovery, switch, persistence, and palette tests pass
under `RUST_TEST_THREADS=1`. Public contract update:
`docs/v0.14.0-profiles-foundation.md`.
