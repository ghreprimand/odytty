## 2026-09-09 -- The /proc churn probe counts its churn

The Linux sole-membership churn probe discarded its spawn results, so a host
that could not spawn the churn processes would have passed it vacuously. The
churn thread now returns how many processes ran to completion and the test
requires at least ten. The foundation document no longer names a "Wayland
compositor adapter"; it names the portal adapter with its explicit
unsupported-compositor fallback, matching the notices.

## 2026-09-09 -- Wayland and macOS shortcut notices tell the truth about the fallback

Review found that the Wayland notices told the user to bind the accelerator in
compositor shortcut settings, but this version exposes no command a compositor
keybinding could invoke to toggle the existing quick terminal; following the
advice would only launch a second ordinary process. The no-portal, refused, and
unconfirmed-binding notices now name the routes that exist: a desktop with the
GlobalShortcuts portal, X11, or Toggle Quick Terminal from the command palette
in an ordinary window. The macOS notice no longer suggests granting
Accessibility or Input Monitoring; Carbon hotkey registration requests neither,
and advising broad permissions for a conflict would be wrong and
security-sensitive. It now names the conflict and points at the logged
OSStatus. Acceptance row QT-WL-NP-02 exercises the palette fallback instead of
an undocumented compositor bind, and the foundation document states the
limitation.

The interactive-Bash file-drop fixtures now name the predicate that timed out,
with a diagnostic snapshot of foreground job, sole-membership, executable, and
launch shell, and a Linux probe pins that the sole-membership scan stays true
for an idle shell while unrelated processes churn `/proc`. The earlier 5 s miss
did not reproduce in sixty repeated runs, under CPU quota, or under churn; no
deadline was raised.

## 2026-09-09 -- Windows automation listener survives a connect-and-close client

The Windows named-pipe listener treated every `ConnectNamedPipe` failure other
than an already-connected or pending result as terminal. A client that connects
and closes before the listener observes it makes `ConnectNamedPipe` report
`ERROR_NO_DATA`; that path recorded a fault, ended listening, and left the pipe
name absent past the CLI's 250 ms missing-name grace, which is what the Windows
CI leg showed in the truncated-frame and close-before-reply cases. The listener
now classifies that outcome as an abandoned instance, creates the replacement
before releasing the consumed instance so the name stays claimed, counts it
against the per-second connection budget, and keeps accepting.

The slowloris case reads the server's bounded rejection as a framed response
instead of assuming one read returns the whole frame; the byte-mode server
writes the length prefix and body separately. Three stale comments were
corrected: the missing-name grace waits before reporting, the CLI's only retry
is that grace, and quick-terminal window attachment can recur after a close or
merge.

Gate: fmt, clippy, 5,464 passed / 0 failed / 29 ignored single-threaded, file
guard, documentation guard, rustsec. One earlier gate run saw the two
interactive-Bash file-drop fixtures miss their 5 s state deadline together; a
rerun and fifteen isolated runs passed, so the cause is unconfirmed and stays
open rather than being treated as fixed.

## 2026-09-09 -- Automation fault lifecycle and Windows pipe test evidence

The listener fault seam now wakes the owner when it records a failure, so a
faulted endpoint is torn down on that event-loop turn instead of waiting for
unrelated activity, and disabling the setting after a fault releases the
resident queue and thread (previously the disabled path consulted the running
check, which a fault had already turned false). A test injection seam records a
fault through the shared cell; a Linux test pins enabled fault to teardown with
the first reason retained, no automatic rebind, retry only after off and on, and
teardown on disable after a fault.

The first Windows CI execution of the named-pipe transport failed three tests
for one transport reason and one expectation. A client that connects and closes
before the listener thread observes the connection leaves the only instance in
its closing state, and `WaitNamedPipe` reports the name absent until the
successor is created on the next poll; the CLI now retries a missing name for a
bounded 250 ms window before reporting it. The slowloris test accepts a bounded
`timed_out` rejection with request id 0 as well as a closed pipe, and the
close-before-reply test asserts at most one owner wake plus listener recovery
rather than zero wakes, since a fully delivered request may legitimately reach
the owner before the disconnect is observed. The quick-terminal
`CreateAndShow` comment now scopes "once" to a live creation reservation or
identity, matching the close/merge recreation path.

## 2026-09-09 -- Quick-terminal lifecycle closure

The quick-terminal controller now reserves its singleton before native window
creation begins, closing the interval where rapid summons could issue duplicate
factory requests. Failed creation clears the reservation for one clean retry;

Linux full-screen/window-manager behavior, macOS Spaces, Windows foreground and

acceptance because the portable window layer can request visibility, position,
and focus but cannot dictate those platform policies.

## 2026-09-09 -- Automation listener faults surface; Windows pipe compiles; hostile-client suite ported

Windows CI on the named-pipe landing failed to build: `OpenProcessToken` lives
under `System::Threading` in `windows` 0.62, not `Security`. The import is
corrected and every other symbol in the file was checked against the crate
source. `CopySid` now writes through a pointer derived from a mutable borrow of
the SID allocation rather than a `cast_mut` of a shared one.

Both transports previously exited their listener thread silently on an accept
error (Unix) or a failed successor pipe instance (Windows), while the runtime
kept reporting the endpoint enabled because it checked only for a dispatch
queue. Each server now records the first terminal failure; the runtime checks
it on every event-loop turn, tears the endpoint down, reports a `stopped`
notice with retry guidance, and `is_running` is false from that point. Worker
thread spawn failures are logged instead of discarded. The Windows successor is
still created before the connected instance is served, so the pipe name never
lapses between clients; a successor failure now ends listening with a reason
instead of serving one last client on a vanished name. The Windows
`peer_finished` contract (disconnected or trailing bytes) is documented as the
Unix mirror, and the response-delivery comment states that closing after a
completed write is pinned empirically by the Windows round-trip tests rather
than guaranteed.

The automation `busy` gate missed two keyboard owners that run before the
overlay ladder: a pending OSC 52 write confirmation, which consumes every key,
and a pointer-owned pane-divider gesture, which the keyboard path settles before
routing. A pending confirmation now returns `busy`, and the divider is settled
at the automation mutation boundary; focused tests pin both.

The Windows hostile-client suite now mirrors the Unix one: zero and `u32::MAX`
length frames, slowloris bodies, a ninth concurrent client deferred rather than
dropped, 33 requests against the accept rate, trailing second frames, close
before reply with no owner wake, a rogue same-user pipe answering with the wrong
request id, `stale_identity` round-trips, and malformed endpoint names including
the extended NT prefix, pid 0, u32 overflow, and embedded NUL. These are
`cfg(windows)` and execute only on the Windows CI leg; the Linux gate compiles
the shared CLI quoting test only.

## 2026-09-09 -- Automation bridge review fixes and three-OS test repairs

Windows file drop now refuses with a notice that names the platform instead of

## 2026-09-09 -- Opt-in Unix automation owner bridge

The bounded local automation protocol now reaches the native event loop on
Linux and macOS when `automation_endpoint` is enabled. Default startup remains
inert; binding waits for the first presented terminal frame. Linux uses the
owner-private XDG runtime directory without a `/tmp` fallback, while macOS uses
an owner-private directory below OdyTTY's existing state location. Startup

## 2026-09-09 -- Confirm-first native path-drop insertion

Native `DroppedFile` events now stage a bounded, ordered path collection behind
the shared risky-paste preview in both single-window and multi-window hosting.
Confirmation rechecks the active pane, bracketed-paste mode, focus, Unix PTY
foreground process group, sole group membership, and launch child's current
shell executable before writing shell-quoted tokens. It never appends Enter,
reads file contents, treats a local path as remote, or accepts terminal-authored
output as input authority.

Linux resolves the launch executable through `/proc/<pid>/exe`, while macOS uses
`proc_pidpath`; bounded group membership comes from a `/proc/[0-9]*/stat` scan
and `proc_listpids(PROC_PGRP_ONLY, ...)`, respectively. Windows explicitly
refuses insertion because ConPTY provides no foreground-process-group
equivalent. The Linux scan skips only entries that vanished mid-scan (ENOENT or
ESRCH) and refuses on any other read error or on more than 65,536 entries. A
process can still join between the membership check and PTY write; that residual
observation race is documented in the foundation contract and shared with close
confirmation. Real-device drop delivery and blocking three-platform acceptance
remain open.

Review found that a pending batch survived when Settings or the Theme Picker
replaced the preview dialog and could resurface on the next drop. Every overlay
opener displaces the dialog the same way, so the fix is one shared reconcile
rather than per-opener cancels: pending paste or drop state that no longer has
its preview dialog showing is discarded at the window-event entry and again
before any new drop is queued. Quoting now also refuses U+2028 and U+2029, which
Unix shells and PowerShell would otherwise receive as raw line separators.

The retained Linux gate passed formatting, Clippy, 5,191 library tests with 16
ignored, all main, integration, and documentation tests, the production file
guard, and the RustSec audit with the time-bounded `ttf-parser` warning allowed.

## 2026-09-07 -- Profile environment entries are validated for OS legality before launch

Named-profile environment overrides now reject shapes that cannot cross the
spawn boundary, so a malformed entry fails at the parse boundary instead of
reaching a spawned child. An empty name, a name containing an equals sign, and a
NUL byte in either the name or the value are refused: an empty name has nothing
to bind, an equals sign collides with the name=value separator used to build the
environment block and leaves the split ambiguous, and a NUL byte cannot appear
in a C environment string. The gate
lives in the schema parser, so it applies uniformly to on-disk load, import, and
the settings editor, whose save routes through the same validation and surfaces
the reason inline without dropping the offending row. Environment names remain
otherwise unrestricted: names with spaces and other non-identifier characters
are legal and round-trip literally. The
local spawn path runs the same gate as defense-in-depth, so a plan built
programmatically from restored state, a connection binding, or a command-line
override fails closed with an error rather than launching a child with a corrupt
environment. Secret-shaped keys and values, and the bounded entry and length
caps, are unchanged.

## 2026-09-07 -- Navigator and connection row menus stay visible in split tabs

## 2026-09-07 -- Session navigator rows gain a right-click context menu

## 2026-09-06 -- Named profiles: launch context now takes effect

A round of hands-on profile testing found the profile editor was solid but a
launched profile did not do what it advertised. Several launch-path defects are
fixed together:

- Environment overrides were dropped for the common case. A profile that set
  environment variables but no shell or command launched with none of them: the
  default-shell spawn path ignored the resolved environment map. Both PTY
  backends now accept the profile environment on the default-shell spawn and
  apply it after the standard interactive-shell setup, so a profile value wins
  over a discovery advertisement, matching the explicit-shell path. On Unix the
  overrides pass through fork/exec; on Windows they fold into the ConPTY
  environment block, the same route TERM_PROGRAM already takes.
- A non-existent starting directory no longer dead-ends a tab. The editor now
  rejects a starting directory the user types or changes that does not exist,
  naming the path, while a directory loaded unchanged from an existing profile
  is preserved even if it is momentarily absent (removable media, an unmounted
  share). At launch, a resolved profile directory that no longer exists falls
  back to home with a bounded notice instead of failing the spawn, on the new
  tab and restore paths alike. Cross-platform: the home fallback is `$HOME` on
  Unix and `%USERPROFILE%` on Windows.
- Deleting or renaming the global default profile keeps the saved default
  coherent. Deleting the profile named as the global default clears the
  `default_launch_profile` key so the next New Tab opens a plain System Default
  tab rather than resolving a missing default; the manager states the default is
  now System Default. Renaming the default rewrites the key to the new name. A
  workspace-scoped launch-profile override that names the deleted profile is
  cleared, and rewritten on rename, so a stale binding cannot outlive the
  profile.
- A profile theme is now visible and durable. The theme a profile selects is
  carried as per-session state, so a global theme sweep (a settings write, an
  OS dark/light flip, a restore seed) re-derives every session's colors
  individually and never flattens a profile tab to the global theme. While a
  profile tab is active the window chrome and GPU present that theme, switching
  back to the global theme on a tab or workspace switch to a plain pane. Colour
  vision adaptation still applies on top. This also resolves a report that
  turning Follow OS theme on then off left a profile tab showing the wrong
  colors: that was the sweep flattening the tab, not a following bug.

Editor ergonomics improved alongside the launch fixes:

- The Theme row cycles the sorted built-in roster plus any user theme files with
  Left/Right, the same way the Shell row cycles discovered shells, and typing a
  name still works. Save rejects an unknown theme name with an inline error
  instead of silently falling back at launch. The roster loads on demand when
  the form opens and never touches the startup path.
- The profile form scrolls under the mouse wheel without moving field focus, and
  the catalog scrolls too; the form shows the same scroll indicator the catalog
  does when more rows sit below the view.
- The catalog filter is started with `/` so the single-key hotkeys
  (d/r/g/x/i/e) no longer steal the first character of a profile name being
  typed as a filter. While filtering, every printable character reaches the
  query; the hotkeys act only with an empty, inactive filter.

Windows behavior is stated per change: environment overrides cross ConPTY, the
home fallback uses `%USERPROFILE%`, and the theme and editor changes are
platform-neutral. Regression coverage spans an end-to-end env-only spawn, the
missing-directory fallback, workspace-binding clear and rename, the profile
theme surviving the sweeps and driving the chrome across a Follow OS toggle, the
theme roster and unknown-name rejection, the wheel scroll, and the `/` filter.

## 2026-09-05 -- Security and correctness hardening

Targeted hardening across input, clipboard, opener, session-host, and terminal
core paths:

- Bracketed-paste sanitizers in both the input encoder and the clipboard chunker
  now converge to a fixed point. A crafted payload that reassembles the paste-end
  marker after a deletion (`ESC[2` + `ESC[201~` + `01~`) previously left the exact
  marker it exists to remove; the scan now checks the growing output tail so a
  reassembled marker is stripped in the same linear pass.
- The "Open With" MIME sniff refuses non-regular files and opens with
  `O_NONBLOCK`, so a hostile program that names a FIFO can no longer wedge the UI
  thread waiting for a writer.
- Hover path resolution memoizes its filesystem probe per pointer cell and
  scrollback position, so the up-to-eight metadata probes no longer re-run on
  every reported pointer motion and a path under a stalled mount cannot repeatedly
  freeze input.
- Openable `file:` hyperlinks are restricted to local targets: a remote or UNC
  authority (`file://host/...`, `file:////server/share`) is rejected rather than
  handed to the OS opener, closing an SMB credential-leak and remote-execution
  path on a single click.
- Detach and switch routes the reported working directory through the shared
  spawn-cwd validator like every other spawn entry point.
- The memory-report diagnostic writes through the hardened, per-user state
  directory helpers instead of a fixed name in the shared temp root, and the
  desktop-notification spawn suppresses the console window on Windows like every
  other console child.
- The theme builder saves through the atomic-write path, so a crash mid-save can
  no longer leave a truncated theme file for the immediate re-read.
- Tab labels strip control characters and advance by display width, closing the
  one cell-grid writer that bypassed the universal control-character backstop.
- Insert and delete character (ICH/DCH) now sever the soft-wrap flag on every
  invocation, since both destroy the right edge; a later resize can no longer
  fuse a wrapped remnant with the row below.
- Tall Sixel images clamp their stored row extent to the screen from the cursor,
  matching the column clamp and the other image protocols.
- The attach client shares one poison flag across its input, resize, and detach
  paths: a truncated write on any of them (a desynced stream) now fails the others
  closed instead of writing further frames onto a corrupted stream, and the attach
  reader grows its frame buffer incrementally like the host reader rather than
  reserving the whole declared length up front.
- Text-selection copy, primary-selection copy, and copy-mode yank reconcile any
  pending scrollback trim before reading, so a copy issued in the window between
  a background output burst evicting history and the next repaint clears a
  now-stale selection rather than copying different, shifted rows.
- The active-prompt input and prompt-start anchors carry the scrollback trim
  epoch and fail closed when eviction has shifted every absolute row, so
  synthesized prompt-editing keystrokes can no longer target the wrong line.
- Sixel decoding gained a per-command painted-column budget, so a repeat-run
  flood that resets the cursor for free can no longer amplify decode work without
  bound; its pixel budget is now aligned to the image store's decoded-byte cap so
  an over-budget canvas is refused before it is allocated and zeroed.
- Inline iTerm2 images check the RGBA expansion against the decoded-byte cap
  before conversion, matching the Kitty path, so a single-channel image that just
  fits the native decode budget cannot expand to several times that on conversion.
- A Kitty image transmitted-and-displayed by number now tags its placement with
  the terminal-assigned id, so the client can delete or address what it drew using
  the id the terminal reported, and two numbered images no longer collide on a
  shared placement id.
- The per-terminal raw graphics-command ring, which copied and retained up to
  64 MiB of payloads that no code read, was removed; the validity gates it existed
  to compute are kept without the copy or the retention.
- Window focus loss now also clears the rename-field drag latch and the cached
  keyboard modifier state, so a drag or a held modifier interrupted by an
  alt-tab cannot resume as a phantom caret move or a phantom modifier on the next
  keypress; and the tab-bar grid recompute skips a zero-size window like the
  primary resize path, so a minimized or pre-configure window no longer forces a
  destructive 1x1 reflow.
- The Keybindings overlay's click-to-row mapping now honors the visible window
  bound, so a click on the panel border or below a scrolled list can no longer
  arm an off-window action. A configuration binding one chord to two actions is
  now surfaced: the chord resolves to a single action and the shadowed action
  shows as unbound, with a warning at load time.
- Workspace-rail context-menu actions re-validate the clicked slot against the
  workspace that was under the pointer at open time, so a background workspace
  closing and shifting the rail can no longer land a Close/Rename/Move on the
  wrong workspace. The font picker strips control characters before measuring, so
  a malformed font name cannot miscount the row width budget.
- Copy File on a Windows UNC path now produces a well-formed `file://host/share`
  URI (host as authority) instead of a four-slash malformed one. The child
  environment builder keeps its set and removed-variable lists disjoint so both
  PTY backends resolve a set-then-removed key identically. Emoji fontconfig
  discovery is gated to Unix-non-macOS like the symbol-font resolver, avoiding a
  console flash on Windows.
- Scrollback search caps its match count, so a broadly-matching query against a
  very large scrollback can no longer build an unbounded result on the UI thread.
  The fuzzy match scorer's inner transition is now an incremental running maximum,
  reducing its worst case from quadratic to linear in the candidate length with
  identical scores.
- The vs-background contrast-floor exemption table and the floor/re-check
  algorithm are now a single shared implementation used by theme generation, the
  colour-vision-deficiency adaptation pass, and the interactive theme author, so
  a future change to one can no longer silently diverge the three.
- The CI build/test workflow declares least-privilege read-only permissions, and
  the informational font-parser advisory exception regained its documented
  removal trigger and pre-expiry early-warning window without moving its date.
- Two confirmation dialogs were widened so their action lines render in full
  rather than clipping the trailing "Cancel", and a batch of stale source-comment
  and module-doc claims across the parser, graphics, font, logging, theme,
  settings, layout, context-menu, about, and native-entry modules were corrected
  to match shipped behavior.
