## 2026-10-04 -- Test-only bidi rendering seam

The cell renderer can now draw a snapshot in bidi display order, through a
seam that only the test suite reaches. No setting, menu, or flag enables it,
and every shipped render path passes no display map, so on-screen output is
unchanged. `BidiDisplayMap` plans each run of soft-wrapped rows as one
paragraph with the headless `src/core/bidi` plans and gives every cell its
visual column, resolved level, and presentation character. Backgrounds,
glyphs, combining marks, decorations, contextual runs, and color glyphs all
draw at visual columns. A wide cell keeps its lead and continuation together,
and each glyph on a reordered row is clipped to its own visual cells. Rows
left in identity layout take the unchanged path.

Mirrored characters in right-to-left text present their Bidi_Mirroring_Glyph
counterpart, generated from Unicode 17.0.0 BidiMirroring.txt into
`src/core/bidi/mirroring.rs` by `scripts/unicode-bidi-data.py`. Characters
with no mirroring counterpart (U+2211, for example) draw unmirrored.
Contextual shaping runs split where the resolved level changes. Arabic
joining runs at a right-to-left level shape right to left. Each shaped glyph
now records its cluster's source cells, so a lam-alef ligature lands on the
visual cells of its lam and alef. Left-to-right ligatures are not formed
inside right-to-left text. The live shaper still shapes left to right in
logical order and decides overlays from glyph ids and source columns only.
The color-glyph builder and coverage-glyph quad helpers moved into
`src/grid/glyph_quads.rs` without behavior change. The test-only counter of cell
color resolutions is now per thread, so concurrently running render tests
cannot disturb the once-per-cell assertion.

Pixel fixtures use a new project-authored, reproducibly generated font,
`tests/fixtures/fonts/bidi-mixed.ttf`. Each mixed-direction line must match
the unchanged renderer drawing the hand-ordered visual string. Fixtures cover
Hebrew with Latin and digits, a mirrored bracket pair, wide cells beside and
inside right-to-left text, a ligature across a direction boundary, Arabic
lam-alef joining, and color glyphs. Byte-identical vertices are pinned for
left-to-right text through the seam. Eight of the eleven fixtures fail with
the display map ignored. Paragraphs that begin in scrollback resolve from
their visible rows only. Cursor, selection, pointer, and search mapping are
not part of this seam.

Validation: format, Linux/Windows/macOS clippy, full locked tests,
production and documentation guards, RustSec, and the fixture-font and
Unicode data regeneration checks passed. The grid, ligature, and bidi tests
passed five runs at the default thread count.

## 2026-10-04 -- Unicode 17.0.0 bidi data and width-0 format controls

The headless bidi display plan in `src/core/bidi` now resolves levels from
Unicode 17.0.0 data, the same version as the width tables. Two new tables are
generated by `scripts/unicode-bidi-data.py`: `classes.rs` holds every
Bidi_Class other than L from DerivedBidiClass.txt, with its `@missing`
default ranges (R, AL, ET, and BN for unassigned code points) applied before
the explicit data lines, and `brackets.rs` holds the BidiBrackets.txt pairs
keyed to their canonical opening bracket. `unicode-bidi` reads both through a
`BidiDataSource` and is now built without its default features, so its
bundled Unicode 16.0.0 tables are not compiled at all.

The two data versions differ on 4,101 code points: 146 assigned characters
and 3,955 unassigned code points whose block default the bundled tables did
not apply (noncharacters and default ignorables are BN, unassigned Arabic
ranges are AL rather than R). Bracket pairs are identical. New tests pin
each kind of class change and show visual order changing where it matters: a
Unicode 17 symbol, a nonspacing mark, or a noncharacter between two Hebrew
letters now reverses with them. Those tests fail against the bundled
Unicode 16.0.0 tables. The full BidiCharacterTest.txt and BidiTest.txt files
still pass in their entirety with the new data.

The plan also gains the control metadata its contract named. A width-0 owner
made only of bidi format controls (embeddings, overrides, isolates, LRM, RLM,
and ALM) keeps its exact logical position, including at the start of a
paragraph or row, takes part in level resolution, and covers no visual
column: its visual span is empty and no column maps back to it. A width-0
owner holding anything else is malformed input and gets the identity layout.

Generated Rust data tables are allowed under `src/` only with a header naming
the generator, each source file and its SHA-256, and "Do not edit by hand";
the production-file guard documents this and measures them like any other
file. No dependency version changes, and both lockfiles are unchanged.
Nothing user-visible changes; bidirectional layout remains unsupported.

## 2026-10-04 -- Antialiased polygon fills for legacy diagonal blocks

Geometric glyph rendering gains a general antialiased polygon filler, and the
Symbols for Legacy Computing diagonal-edged blocks (`U+1FB3C..U+1FB67`) and
negative diagonals (`U+1FBBD..U+1FBBF`) now render from cell geometry when
`geometric_boxdraw` is on, instead of falling back to a font or a missing-glyph
box. These were the last recorded holes in the geometric legacy-symbol set.

The filler computes the exact area of a polygon inside each pixel by clipping
it to the pixel square, so edges are antialiased without supersampling, any
simple polygon works in either winding, and overlapping polygons clamp to one
fully inked pixel. Each diagonal block is the cell cut by one line between
anchors named in its Unicode character name (left, centre, right; upper,
upper middle, lower middle, lower), keeping the named corner's side. Each
lower fill and the upper fill 22 codepoints later share the same line, so
they tile into one solid cell. The negative diagonals are a fully inked cell
with light strokes cut out, at the same thickness as the box-drawing
diagonals, so `box_thickness` applies to them.

New tests check all 47 codepoints for bounded, non-empty, non-solid coverage
at five cell sizes from 6x12 to 18x36. They also check that complementary
pairs sum to full coverage within one unit, that mirrored neighbours match on
their shared edge, and that four glyphs match independently computed rational-area fixtures within eight
units (measured maximum difference: one). FNV-1a hashes of every previously
covered geometric glyph at the same five sizes (3,800 records, frozen before
this change) are unchanged. The four diagonal tests fail on the previous
renderer. The glyph corpus moves both ranges from its deferred-holes section to
a covered section. With `geometric_boxdraw` off, these codepoints use the font
path as before. Performance is unmeasured.

Local gate: cargo fmt --check, Linux, Windows and macOS clippy, the full single-threaded test suite (6,032 passed, 0 failed, 30 ignored), the production-file and documentation guards, and the RustSec audit pass.

## 2026-10-03 -- Headless bidi display plan with pinned UAX #9 conformance

A new core module, `src/core/bidi`, computes the Unicode Bidirectional
Algorithm layout of one wrapped logical line without changing any display,
input, selection, copy, or stored cell. The paragraph is the wrapped logical
line with its level forced to left to right. Levels are resolved once per
paragraph, then the line rule and reordering run on each physical row, so a
cell never moves to another row. Owners (a base scalar with its attached
marks, a blank, or a wide pair) move as one unit, and a wide owner keeps its
two cells adjacent with the lead first. The result is an immutable plan with
per-owner levels, widths, and mirrored-glyph flags, plus reversible
owner-to-visual-span and visual-column-to-owner maps. Text that cannot
resolve to a non-zero level skips all bidi work. Paragraphs over 16,384
owners, 262,144 bytes of owner text, or 16,384 rows, and malformed input, get
the complete identity layout rather than a partly reordered one. Each cap is
tested at its exact boundary. Performance is unmeasured.

Conformance is pinned to Unicode 17.0.0. The full BidiCharacterTest.txt
(91,707 cases) and BidiTest.txt (770,241 cases across paragraph directions)
pass in their entirety. A strided subset of each (2,894 and 12,022 cases) is
committed under the Unicode License v3 and asserted case-for-case in the
regular suite. Left-to-right cases run through the public plan; right-to-left
and auto-direction cases exercise the same level resolution, line rule, and
reordering directly. Rules L3 and L4 are outside both files: marks never leave
their owner, and mirroring is reported as a flag. Bidi_Mirrored data is
generated from Unicode 17.0.0 by `scripts/unicode-bidi-data.py`.

New dependency: `unicode-bidi` 0.3.18 (MIT OR Apache-2.0, no transitive
dependencies), chosen for maintained UAX #9 level resolution rather than a
second hand-written implementation. It bundles Unicode 16.0.0 bidi classes
while OdyTTY's width tables are Unicode 17.0.0, so characters assigned or
reclassified in Unicode 17 resolve with their Unicode 16 class until a Unicode
17 class source is supplied. Both lockfiles are updated and the RustSec audit
passes. Nothing user-visible changes; bidirectional layout remains
unsupported.

Local gate: cargo fmt --check, Linux, Windows and macOS clippy, the full single-threaded test suite (0 failed), the production-file and documentation guards, and the RustSec audit pass.

## 2026-10-03 -- Wide-glyph padding preserves logical text

storage, and snapshot format v4. Eager and lazy resize discard old generated

## 2026-10-03 -- Argument launches keep the saved workspace layout

A launch with any command-line argument skipped workspace restore but still
owned the shape autosave, so the argument session replaced the saved layout on
its first structural change or on quit, and the next bare launch restored the
wrong layout. Ownership of the saved shape now requires both the instance lock
and a bare launch. A process launched with arguments writes no snapshot for
its whole lifetime: not the debounced autosave, the cwd checkpoint, a profile
binding edit, nor the clean-exit save, and no later window inherits ownership
through a close, merge, or move. It still holds the instance lock, so a
concurrent bare launch remains a secondary window, and it raises no
secondary-instance notice. Linux, macOS, and Windows share the rule and the
persistence path.

## 2026-10-02 -- Stacked and floating pane layouts

- A tab keeps its split tree as the single record of which panes exist and
  adds an arrangement beside it: tiled (the default, and the only mode older
  layouts know), stacked, or floating. **Stack Panes**, **Float Panes**, and
  **Tile Panes** are palette actions; no default chord was added. Switching
  mode never restarts a pane, and Tile returns the exact tiled geometry
  because the tree is never discarded.
- Stacked shows the focused pane over the whole content area while the other
  panes keep running at their tiled size. Floating panes are whole-cell
  rectangles with a z-order, a frame, an 8 x 2 cell minimum, and a clamp at
  resolution time, so a smaller window never deletes a pane. The focused pane
  is always painted on top; focus cycling stays in stable tree order so every
  pane is reachable, and **Focus Pane k of n** palette rows list them.
- **Arrange Floating Pane** moves (arrows) and resizes (Shift+arrows) the
  focused floating pane from the keyboard. Overlapping panes are cut around
  the panes painted above them for backgrounds, glyphs, and overlays. Known
  limits: pointer drag of a floating frame is not implemented, and a covered
  floating pane draws no inline images until it is uncovered.
- Persistence writes an `arrangement` object only for non-tiled tabs, so
  tiled layout files are byte-identical. Malformed or partial entries load
  tiled or as an unplaced pane, never as a partial rectangle; restore is
  deterministic. A pane moved from another window joins the destination tab
  as a floating pane only when that tab is floating.
- New feature, no performance claim. Gate: fmt, Linux plus Windows and macOS
  cross-target clippy, single-threaded tests (library 5695 passed, 0 failed,
  16 ignored), file and doc guards, and RustSec all passed. Device acceptance
  on Linux, macOS, and Windows is pending.

## 2026-10-01 -- Ambiguous character width preference

- `ambiguous_width` (`ODYTTY_AMBIGUOUS_WIDTH`, profile `appearance.ambiguous_width`)
  chooses how East Asian Ambiguous characters are measured: `narrow` (the
  default, today's width table, one column) or `wide` (two columns, using
  the width crate's East Asian context table). A pane follows the profile
  that launched it; a missing profile value uses the global setting.
- Changing the value reflows that pane's primary grid and scrollback in
  place through the existing resize path. The PTY is not resized and the
  shell is not told, so a prompt drawn under the old width stays as drawn
  until the shell repaints it; a selection or search hit can land on
  different cells after the remeasure. An active alternate screen is left
  for the application to repaint. Width policy is part of the projection
  cache key, so a same-width policy change never reuses old row counts.
- Overlay chrome, the tab bar, the search status line, and the glyph atlas
  stay on the narrow table: a shared atlas cannot cache two slot widths for
  one codepoint while two panes disagree, and the grid's continuation cell
  reserves the second column. IME pre-edit follows the pane's policy.
- Verification: fmt, Linux plus Windows/macOS cross-target clippy,
  single-threaded `cargo test` (5610 library tests passed, 16 ignored), the
  guards, and both RustSec audits pass; width conformance and the new
  ambiguous-width tests cover both tables and the reflow. Hands-on Linux
  acceptance is pending.

## 2026-10-01 -- Move tabs and panes between windows

- A tab or a pane can move to another window of the same process, or into a
  window of its own, from the command palette: Move Tab to New Window, Move
  Tab to Window..., Move Pane to New Window, Move Pane to Window.... The "to
  Window..." rows reuse the merge picker: each other window shows a numeral
  and "Press N to move here". Rows appear only when they can work (a sibling
  window exists, something stays behind, the tab is split).
- The moved shell keeps running. Its PTY or attached session, writer, pump,
  terminal model, scrollback, images, selection, search, recorder, profile
  binding, and `--hold` state move as owned values between the two workspace
  arenas; nothing is respawned, detached, or replayed. A moved tab keeps its
  panes and layout; a moved pane becomes the only pane of a new tab whose
  identity is minted from the destination's token range, and the pane it
  leaves behind takes over its split.
- The move is a transaction: a preflight checks token collisions and
  capacity without mutating either window; a refused destination or a new
  window that cannot open restores the tab index, workspace, pane tree,
  focus, and zoom exactly, with a notice. Before a pane leaves, the source
  settles the state that names it (focus-out report, pending paste and image
  confirmations, IME composition, context-menu target, open overlay, drags)
  and afterwards prunes OSC 52 consents and reflows. The destination drops
  its presentation caches, parks timers, applies its presentation policy,
  activates the tab, and reflows.
- Moving a window's last tab retires that window, and the primary autosave
  role moves to the destination. The quick terminal neither sends nor
  receives. Attached host-session ids are shared across windows, so a session
  attached in another window is refused with a notice rather than attached
  twice.
- Drag tear-out is not supported: on Wayland the compositor owns placement
  and winit reports no cross-window drag, so the palette is the route there
  and on every other platform.
- Chosen, and reversible: palette rows only (no context-menu rows yet); a
  window's only tab does not move to a new window; a moved pane keeps its own
  recorder state; an open command-export save dialog stays with the window
  that opened it while the export follows the pane.
- Verification: fmt, Linux plus Windows/macOS cross-target clippy,
  single-threaded `cargo test` (5617 library tests passed, 0 failed), the
  guards, and both RustSec audits pass; 5 model tests and 9 host/App tests
  cover the picker move, last-tab retire with primary handoff, pane to a new
  window with hold, IME, and focus-out, exact restore when the new window
  cannot open, only-tab and quick-terminal refusals, cross-window attach
  dedup, and the palette rows. Hands-on acceptance on Linux (including NVIDIA
  window create and destroy), macOS, and Windows is pending.
