# External palette following (v0.14)

Public feature name: **External palette following**.

When enabled, OdyTTY monitors one explicit local palette file, applies only
complete valid palettes through the existing theme seam, and retains the last
known-good palette across missing, partial, malformed, or transient replacement
states. Existing theme behavior (built-ins, `theme = system`, custom theme
files, profile appearance theme names) is unchanged unless following is
explicitly selected.

## Settings

| Key | Env | Default | Meaning |
| --- | --- | --- | --- |
| `follow_external_palette` | `ODYTTY_FOLLOW_EXTERNAL_PALETTE` | off | Opt-in follow mode |
| `external_palette_provider` | `ODYTTY_EXTERNAL_PALETTE_PROVIDER` | `odytty` | Source format |
| `external_palette_path` | `ODYTTY_EXTERNAL_PALETTE_PATH` | unset | Explicit file path |

The Settings panel also shows a read-only **External palette status** row. It
reports `off`, `watching`, `applied`, retained last-known-good state, or a
bounded validation/read error. The row refreshes after settings apply, startup
activation, and file polling; it does not change the configured source.

The Profile Manager exposes the same follow, provider, and path fields under a
profile's appearance settings. Profile values participate in the documented
profile precedence chain. Enabling following in a profile requires an explicit
path, and provider values are validated before the profile is written.

Providers:

- `odytty` - explicit OdyTTY theme-format file requiring a complete color
  payload, or a complete Base16 `base00`..`base0F` map with the documented
  projection in `src/external_palette/parse/odytty.rs`.
- `colors_toml` - current named-color and legacy indexed flat `colors.toml`
  schemas, including Omarchy-compatible files (independent compatibility).
- `colors_json` - pywal-compatible `colors.json` (independent compatibility).

Support for third-party formats is independent. This document makes no claim of
endorsement, partnership, official integration, or required upstream
modification.

## Precedence

When `follow_external_palette` is on and a last-known-good complete palette
exists, that palette drives presentation. Otherwise resolution falls through to
OS dark/light following (`theme = system` / `follow_os_theme`) and then the
authored theme. Live UI edits and settings reload reconfigure the follower;
terminal output cannot select a source, supply a path, rewrite configuration, or
trigger a load.

## Startup isolation

Ordinary default launch performs no palette discovery, read, parse, or poll.
The follower arms only after follow is enabled with an explicit path. Content
fingerprints hash file bytes (not mtime+length), so same-metadata content
replacement still reloads and identical-byte mtime touches do not.

## Platform notes

Linux, macOS, and Windows all support following an explicit local filesystem
path. There is no desktop-palette discovery API in this packet; the watched
path is always user-configured.
