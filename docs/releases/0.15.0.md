# OdyTTY v0.15.0

Version 0.15.0 adds a dedicated quick terminal, owner-scoped structural
automation, confirm-first external file drop, keyboard-first window merging, and
the Electric Blue theme, while preserving the existing terminal input and
remote-upload security boundaries.

Electric Blue adds the `odyssey-electric-blue` preset: a blue-black background,
lavender text, an electric cyan cursor, and distinct ANSI colors. It uses the
existing shared theme parser, picker, settings, and export paths on Linux,
macOS, and Windows without changing the default preset or effect settings.

## What this release adds

- **Quick terminal.** A dedicated drop-down terminal with its own identity and
  settings, summoned by a global shortcut. Shortcut registration is
  platform-specific (Linux X11, Wayland through the GlobalShortcuts portal or an
  actionable limitation, macOS, Windows) and never reports success without
  platform confirmation. The hidden session is retained, repeated summons never
  duplicate it, registration happens only after an ordinary frame, and denied or
  conflicting registrations raise actionable notices. Placement on tiling Wayland
  compositors is compositor-controlled.
- **Local automation.** An opt-in `automation_endpoint` (default off) that binds
  after the first presented frame. Linux and macOS use owner-private sockets;
  Windows uses `\\.\pipe\odytty-control-<pid>` with an owner-only DACL,
  remote-client rejection, and mutual SID checks. The protocol is structural
  only: it lists and focuses windows, workspaces, tabs, and panes, opens
  profiles, creates tabs, splits, and workspaces, renames, and reports
  non-sensitive status. It never sends terminal input or reads terminal content.
  A small `odytty control` CLI drives it with machine- and human-readable output.
- **External file drop.** Confirm-first, shell-quoted insertion of dropped paths
  on eligible local panes through the shipped paste-safety policy; a path is
  never executed and no Enter is appended. Native Wayland delivery is supplied by
  a companion non-owning `wl_data_device` listener on winit's connection, since
  winit emits no Wayland drop event of its own. OdyTTY requests Copy only and
  performs no file operation itself; the Hyprland admission rule and its exact
  residual are documented in the
  [v0.15.0 contracts](../v0.15.0-foundation.md#drag-action-negotiation-and-the-hyprland-admission-rule).
  Windows refuses file drop with an explicit notice; remote and attached panes
  refuse local paths; the integrated-SSH image-upload path stays separate and
  confirm-first.
- **Keyboard-first window merge.** Palette and Session Navigator merge and pull
  with stable window identities, temporary numerals painted inside candidate
  windows, and an atomic same-process transfer of tabs, panes, PTYs, and attach
  handles. The source window closes only after a successful transfer.

## Fixes and hardening

A pre-existing correctness bug is fixed: a shell spawned by OdyTTY inherited
ignored SIGINT/SIGQUIT dispositions when OdyTTY itself was launched as a
background job, so Ctrl+C could fail to reach foreground commands. PTY children
now start with default signal dispositions. The new automation and file-drop
subsystems ship with owner-only access, fail-closed insertion authority, and
hostile-client hardening rather than as best-effort additions.

## Platform notes and limitations

- Quick-terminal window placement on tiling Wayland compositors is decided by the
  compositor, not OdyTTY.
- On Hyprland, file drop is admitted by the compositor's drag behavior rather
  than by name; a source that offers only Move, or a compositor that answers with
  a non-Copy action, is refused.
- A non-UTF-8 filename dropped on X11 is not delivered by winit and produces no
  event; OdyTTY cannot surface a notice for a drop it never receives.
- File drop is refused by design on Windows.
- Automation is off by default and owner-scoped; cross-account and cross-machine
  access is refused by the socket/pipe ownership itself.

Device acceptance was performed on Linux (native Hyprland/Wayland and nested
KWin), Windows, and macOS. Full per-row results, including the rows that are
unsupported by the available hardware, are recorded in
[acceptance/v0.15.0.md](../acceptance/v0.15.0.md).
