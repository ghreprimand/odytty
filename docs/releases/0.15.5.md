# OdyTTY v0.15.5

Version 0.15.5 moves OdyTTY's text font reading to a maintained font library
without changing how text looks, and fixes two Wayland reliability problems: a
window that could stop repainting after a lost frame callback, and a focused
idle window that could hold one CPU core busy.

## Font stack maintenance

- **Maintained font parsing.** Normal-text font metadata, metrics, and glyph
  outlines now come from the Fontations `skrifa` library behind an
  OdyTTY-owned font handle. The existing glyph coverage rasterizer is unchanged.
  On a frozen corpus of bundled faces, sizes, and subpixel positions, the new
  path produced the same metadata, metrics, bounds, and 8-bit glyph coverage as
  the previous path in every sampled case, and controlled Wayland and Xwayland
  screenshots were byte-identical before and after the change.
- **Wayland title bar.** When the compositor asks OdyTTY to draw its own title
  bar, the title text is now drawn through the system FreeType and Fontconfig
  libraries (crossfont) instead of a bundled parser. Compositors that draw
  their own decorations, and macOS and Windows, are unaffected.
- **Dependency advisory closed.** The unmaintained `ttf-parser` crate
  (RUSTSEC-2026-0192), together with `owned_ttf_parser` and `ab_glyph`, no
  longer appears in the application or standalone fuzz dependency graphs, and
  the dated audit exception for it is removed.

## Reliability fixes

- **Wayland repaint recovery.** A focused, visible Wayland window whose
  compositor never returned a frame callback could stop repainting while the
  shell kept running. After a redraw has been owed for about two seconds, OdyTTY
  now paints directly at a bounded rate until the compositor responds, and the
  freeze watchdog records this state under its own name. The original trigger
  was not reproduced locally; the recovery path is covered by deterministic
  tests.
- **Idle CPU on Wayland.** A focused, idle window could keep one CPU core fully
  busy because timed animations requested an immediate redraw while also
  scheduling a timed wake. Timed redraws now wait for their deadline. On the
  measured Linux workstation, focused idle CPU dropped from about one full core
  to zero once the cursor stops blinking, with cursor, scroll, bell, and fade
  animations unchanged. X11, macOS, and Windows did not show the loop.

## Platform notes and limitations

- **Linux system libraries.** Linux binaries now link the system FreeType and
  Fontconfig libraries, which standard desktop installations already provide;
  the `.deb`, `.rpm`, and AUR packages already list them. Source builds need
  their development packages and `pkg-config`; see the
  [install guide](../install.md#build-from-source-1). macOS and Windows are
  unchanged.
- **How text is drawn.** The [feature reference](../features.md#how-text-is-drawn)
  describes the complete text rendering path.
- **Validation.** Blocking Linux, macOS, and Windows CI passed for each change.
  Linux Wayland and Xwayland rendering, the client-side title bar under Weston,
  display-scale moves, plain render quality, and multi-window GPU close were
  checked on device. On macOS and Windows, ordinary text, styles, emoji,
  symbols, box drawing, wrapping, and font-size changes were checked on device.
- **Not measured for this release:** cold (first launch after reboot) startup
  time, the formal exact-geometry memory guard, scripted typing and selection
  checks over mixed-width and right-to-left text, and display-scale moves on
  macOS and Windows. Warm startup and idle memory were compared before and after
  the font change and were unchanged within measurement.
- **CJK fallback.** With default fonts, the tested Han characters display as
  missing-glyph boxes on Linux, macOS, and Windows, as in v0.15.0. They render
  when a covering font is supplied through the `symbol_font` setting
  (`ODYTTY_SYMBOL_FONT`). Automatic CJK font discovery is not part of this
  release.
- **Known Windows issues (also in v0.15.0).** With a long, wrapped PowerShell
  prompt, the first typed command can start away from the prompt, and
  Ctrl+Shift+N can insert an `n` and move the cursor of the original window.
  Both are scheduled for a later release.
