# OdyTTY v0.15.7

Version 0.15.7 prevents Wayland windows from stopping updating after they
return from a hidden workspace, a stall observed with NVIDIA's proprietary
driver, and keeps
workspace autosave working after the primary window is merged into another
window.

## Fixes

- **Wayland windows no longer stall after a hidden workspace.** On Wayland
  with NVIDIA's proprietary driver, a window could stop updating for minutes
  or hours after its workspace was hidden and shown again, while the terminal
  behind it kept running. Under the default `Fifo` present mode, that driver
  paces frames through the compositor's commit-timing protocol, and it was
  observed to ask for a frame to be shown seconds in the future right after a
  window returned from a hidden workspace; a stalled window's held target was
  about 3.5 hours ahead. A compositor that honors the target, as Hyprland
  does, holds every later update of that window until then. OdyTTY now
  presents with `Mailbox` on every Wayland surface that offers it; under
  `Mailbox` NVIDIA's driver sends no commit-timing requests. Redraws are
  already paced by the compositor's frame callbacks, so the extra throttle of
  `Fifo` is redundant on Wayland, and both modes use three swapchain images. The startup log names the chosen present mode.
- **Merging the primary window keeps workspace autosave.** Since v0.15.0,
  merging the first window of a process into another window, or pulling it
  into another window, left the surviving window without autosave, so later
  layout changes were not saved for the rest of the session. The surviving
  window now takes over autosave and saves the merged layout. Merging another
  window into the primary window is unchanged.

## Platform notes and limitations

- **Where the present-mode change applies.** Wayland sessions on every GPU
  driver change when the surface offers `Mailbox`. Windows, macOS, and Linux
  X11 keep `Fifo` with no behavior change. The change was checked on device
  only with NVIDIA's proprietary driver. Mesa 24.3.2 and later send
  commit-timing requests for Vulkan `Fifo` on Wayland only for presents that
  carry a presentation time; the far-future targets seen with NVIDIA's driver
  have not been reproduced on Mesa drivers, and AMD, Intel, and NVK were not
  tested on device.
- **Validation.** Blocking Linux, macOS, and Windows CI passed on the tagged
  commit. On Linux (Hyprland with NVIDIA's proprietary driver), a protocol
  trace showed no commit-timing requests under `Mailbox`, the startup log
  named `Mailbox`, and the workload that previously stalled ran for about two
  hours on a hidden workspace without a stall. The autosave fix is covered by
  tests for both merge directions. No macOS or Windows device checks were run
  for this release, and rendering speed, idle CPU, and memory were not
  re-measured.
- **Known Windows issues (also in v0.15.0 through v0.15.6).** With a long,
  wrapped PowerShell prompt, the first typed command can start away from the
  prompt, and Ctrl+Shift+N can insert an `n` and move the cursor of the
  original window. Both are under investigation for a later release.
- **CJK fallback.** With default fonts, Han characters still display as
  missing-glyph boxes, as in v0.15.6; a covering font can be supplied through
  the `symbol_font` setting.
