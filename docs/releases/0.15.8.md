# OdyTTY v0.15.8

Version 0.15.8 stops an untouched macOS window from staying busy. Idle CPU
returns to about zero. The cause is a per-tick clone of the event-loop proxy
inside `about_to_wait`, which re-wakes the macOS run loop. That clone has been
present since v0.15.0.

## Fixes

- **macOS idle CPU.** An untouched window could keep one core busy because
  every event-loop tick cloned an `EventLoopProxy`. On macOS that clone
  registers a run-loop source and wakes the loop, so the tick never goes idle.
  The tick path no longer clones the proxy. An untouched window's idle CPU
  returns to about zero.

## Platform notes and limitations

- **Linux and Windows.** Proxy clones there are cheap and showed no spin. The
  per-tick clone is removed on those platforms too. This release makes no
  idle-CPU claim for Linux or Windows.
- **Where this was seen.** The busy loop was observed on macOS. The per-tick
  clone has been present since v0.15.0.
- **Validation.** macOS acceptance is an untouched window whose idle CPU
  returns to about zero, before and after on the same Mac. Rendering speed
  and memory were not re-measured. Linux and Windows have no idle-CPU claim.
- **Known Windows issues (also in v0.15.0 through v0.15.7).** With a long,
  wrapped PowerShell prompt, the first typed command can start away from the
  prompt, and Ctrl+Shift+N can insert an `n` and move the cursor of the
  original window. Both remain open on this branch.
- **CJK fallback.** With default fonts, Han characters still display as
  missing-glyph boxes, as in v0.15.7; a covering font can be supplied through
  the `symbol_font` setting.
