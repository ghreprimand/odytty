# OdyTTY v0.17.5

Version 0.17.5 extends bounded text ownership and font shaping beyond the
previous script groups, adds joining scripts and paragraph direction controls,
and corrects font fallback, cursor coverage, image extents, Windows
transparency and Sixel transport, session startup, detached launches and tab
release. Cell
addressing, selection, search, copy, wrapping and reflow retain their logical
semantics.

## Text and display

- **General cluster ownership.** Unicode properties extend bounded ownership
  beyond the tuned script groups, including text split across program writes.
  The terminal width profile retains its documented differences from Unicode
  grapheme segmentation. Mode 2027 is permanently set: its query reports set,
  and requests to disable it leave ownership unchanged. The
  [specification](../../SPEC.md#grapheme-cluster-mode-dec-private-mode-2027)
  records the profile and bounds.
- **Font shaping.** With `script_shaping` on, supported multi-scalar owners
  outside the tuned groups also use font shaping. A font must cover the owner;
  missing coverage retains scalar fallback. Shaping stays inside bounded cell
  ownership. An oversized shaped cluster can use a following blank cell,
  without overwriting text there. Block cursors and unfocused outlines cover
  the complete one- or two-cell owner; shaped ink is clipped to that span,
  and color emoji retain their RGBA pixels. Glow, trail and large-jump follower
  rectangles use the same owner width. Bars and underlines keep their size.
  Spacing marks on the scalar fallback path retain their cell positions.
- **Joining beyond Arabic.** Syriac, N'Ko, Mandaic, Adlam, Hanifi Rohingya and
  horizontal Mongolian take contextual forms with script shaping enabled.
  A run whose letters are absent from the text font joins from a fallback
  face that maps them all. Joining requires font coverage; a proportional
  face can leave gaps between letters. Vertical Mongolian and historic joining scripts remain outside the
  supported joining groups. The [shaping reference](../shaping-roadmap.md)
  lists the script and mark boundaries.
- **Font fallback.** Printable ASCII uses the first covering fallback face
  when the primary face lacks a glyph. A primary that covers ASCII keeps its
  existing atlas data. Fallback letters and digits fit inside their source
  cells even when the primary font has narrow metrics. Icons and combining
  marks retain their overflow placement. On macOS, Grantha resolves from face 1 of the system
  Tamil Sangam MN collection; Tamil keeps face 0.
- **Retained combining marks.** A nonspacing/enclosing mark whose font glyph
  has a positive advance is anchored back over its base, preventing atlas
  clipping and loss during block-cursor redraw. Normal/styled content and bidi
  display share the correction. Zero-advance marks, spacing marks and fitted
  symbol overrides retain their placement; logical text and widths do not change.
- **Color keycaps.** A VS16 keycap shapes without its selector unless the
  color font's ligature consumes it, allowing Apple Color Emoji to draw it
  in color. Logical text, width and cache identity retain VS16.
- **Updated shaping engine.** `harfrust` 0.14.0 resolves the recorded Bengali
  ka, virama, ra difference from the HarfBuzz reference. This does not imply
  that every font or sequence matches the reference.
- **Paragraph direction and full-screen text.** Opt-in `bidi_reorder` now
  applies on the primary and alternate screens. `bidi_direction` selects left
  to right, right to left or automatic direction in Settings > Rendering and
  the right-click menu. Programs can select paragraph direction with SCP and
  explicit layout with `CSI 8 l`; `CSI 8 h` restores implicit layout. Explicit
  mode and direction persist across screen switches until changed or reset.
  Complex-script owners move as whole spans. Cells, cursor reports, mouse
  reports, selection and copied text stay logical.
- **Images and overlays.** Rows covered by Sixel, Kitty or iTerm2 images keep
  logical order during bidi display. Menus, panels and rename fields retain
  the terminal display map beneath them. Image protocols share the remaining
  scroll-room bound without scrolling to make room.
- **Replay preview emoji.** With reordering on, or in a split tab, the
  Session Replay preview is drawn as a separate window layer. A recorded emoji
  there now draws as the same color glyph the terminal draws, over the replay
  panel and below a rename field opened on top, instead of a missing-glyph
  box. An emoji the color font does not cover keeps its monochrome glyph.
  Other script clusters in that layer still draw cell by cell rather than
  shaped; text attributes and colors are not shown in the preview.
- **System CJK fallback.** Windows and macOS try installed CJK faces after
  the primary and static chains miss. The fixed order does not infer language
  or regional Han forms from the locale. Missing system coverage still draws
  boxes; disabling symbol fallback disables this lookup.

## Windows, tabs and sessions

- **Windows transparency.** Window transparency now works through DX12
  DirectComposition with a matching window style. The default stays on at 80;
  `window_opacity = 100` keeps the window solid. A failed Visual startup retries
  in an ordinary opaque HWND window. Settings states when the current surface
  cannot be transparent, including other opaque Windows backends.
- **Bundled Windows console runtime.** Windows PTYs use Microsoft ConPTY
  1.25.260930003 from the package's `runtime/` folder, which carries Sixel
  output through to the terminal. Its native files are checked against
  embedded sizes and hashes offline before the first PTY starts; missing or
  altered files produce a reinstall error rather than a fallback to the
  system console. Install and upgrade the complete extracted folder,
  including `runtime/` and `licenses/`, beside `odytty.exe`; the full
  publisher notices are under `licenses/conpty/`. Source builds stage the
  verified runtime explicitly. The
  [install guide](../install.md#bundled-windows-console-runtime) lists the
  layout and limits.
- **X11 tab release.** A drag preview follows the pointer. Release retires
  that preview and opens an ordinary window around the same session, PTY and
  history. A tiling window manager places the new window; floating managers
  can honor the requested drop position. Escape, return to the source strip
  and preview close cancel the move. Live tab drag can still be disabled in
  Settings > Layout.
- **Ambiguous width at startup.** New sessions apply their width policy
  before terminal output arrives. On Unix, an attached session's host starts
  with the launching window's ambiguous width for Detach & switch, or the
  configured width for `odytty new`. Later setting changes reach only the
  window's mirror: the program's cursor reports keep the host's starting
  width. Windows has no detached session host.
- **Detached sessions.** Capturing the output of `odytty new --detached` no
  longer hangs, and the session host no longer stays in the launching
  terminal's job control. Windows has no detached session host.
- **macOS child locale.** A Dock or Finder launch with LANG, LC_ALL and
  LC_CTYPE all unset supplies child processes with an installed UTF-8 locale
  from AppleLocale, falling back to en_US.UTF-8. Explicit inherited and profile
  locale values, including empty values, are preserved. Logical copy and
  clipboard bytes are unchanged. Linux locale inheritance and Windows ConPTY
  behavior are unchanged.
- **Correctness fixes.** Triple-click selection uses the whole logical line
  across soft-wrapped rows. Authorization header redaction accounts for escaped
  values. On Linux, a file drop into an idle launch shell is no longer
  refused when an unrelated process exits during the foreground scan.
  Test temporary directories tolerate spaces and are checked for leftovers.

## Performance and known limits

Bidirectional reordering remains **off by default**. Its measured Linux cost
exceeds the default-on threshold, even with cached plans for unchanged frames.
Windows and macOS per-frame cost is unmeasured. Enabling it remains a live,
optional display choice; the [feature reference](../features.md#ligatures-shaping-and-bidirectional-text)
records the measured Linux ratios and settings.

Measured shaping costs remain recorded costs, not recovered regressions.
The `harfrust` 0.14 comparison found a Devanagari cold frame about 20 percent
slower, from 150 to 181 microseconds, and the parser-only scroll churn row
about 18 percent slower, from 256.7 to 302.9 microseconds; the full-terminal
scroll-region churn row on the same input moved 1.4 percent, which is neutral.
The [memory and performance notes](../memory.md#shaping-engine-comparison)
record this residual and its measurement limits. Other measured changes
reduce selected reflow, shaping, projection and test-device costs; they do not
establish a universal frame-time improvement.

The combined ASCII fallback, Grantha fallback, Chakma label, wide-owner cursor
and macOS locale corrections were measured against 1cc645a8 with the frozen
internal-1 protocol on the Linux AMD Ryzen 9 9950X3D desktop class, using thirty
paired runs. Four of 67 rows exceeded their frozen 3% regression thresholds:
DECFRA fill +3.078%, DECSERA protected erase +4.391%, cursor_tail_only()
+19.623% (7.695 to 9.205 ns per call), and bidi ASCII live four-pane frame
+3.240%. These combined results do not identify a cause or attribute a change
to an individual correction; no speedup is claimed. Cold missing-ASCII fallback,
distinct wide/RGBA cursor redraw, native effects/GPU, macOS/Windows execution
and locale startup remain unmeasured. The
[shaping notes](../shaping-roadmap.md#text-correction-costs) record the scope.

The narrow-primary fallback fit correction was compared against 943557f2
with the frozen internal-1 protocol on the Linux AMD Ryzen 9 9950X3D desktop
class, using thirty paired runs. Of 67 rows, 63 were neutral, three classified
as improved, and one exceeded its regression threshold: `parser scroll churn
10000` moved from 254.798 to 314.214 microseconds, +23.319% against a 5.199%
threshold. This comparison does not establish a cause for that movement; no
speedup is claimed. Cold narrow-primary fallback/atlas construction, native
GPU work and macOS/Windows runtime remain unmeasured.

The retained combining-mark correction was compared against 4ba0cb36 on the frozen internal-1
protocol on the Linux AMD Ryzen 9 9950X3D desktop class, using thirty paired
runs. Of 67 rows, 62 were neutral, two classified as improved, and three
exceeded their 3% regression thresholds: `resize reflow (deep scrollback)`
rose from 181.475 to 189.848 microseconds (+4.614%); `resize reflow
(height-only, deep)` rose from 156.848 to 163.283 microseconds (+4.103%);
and `CI documentation guard` rose from 31.863 to 34.179 milliseconds
(+7.270%). No cause for those movements or speedup is established. Cold
positive-advance mark insertion, native GPU work and macOS/Windows runtime
remain unmeasured.

macOS CJK fallback may select the Hong Kong face of the system CJK collection.
Regional glyph selection remains a risk pending macOS hands-on acceptance.
The [feature reference](../features.md) and
[shaping reference](../shaping-roadmap.md#current-support-boundary) describe the
remaining font, script and display limits.

## Platform acceptance

Every change in this release passed blocking build and test CI on Linux,
macOS and Windows. Hands-on checks on development revisions before this
release candidate covered the following:

- **Linux:**
  - The link pointer, and triple-click and drag copy on wrapped lines.
  - Replay preview color emoji with bidi display off and on in a single
    tab, and off in a split tab, with no stale glyphs and the replay isolated
    from the shell.
  - A rename field and Settings open together during bidi display.
- **X11:** tab release under two real X11 window managers.
- **Windows:**
  - Sixel image pixels and resize through the bundled console runtime, and
    the package and runtime layout.
  - Image rows during bidi display.
  - Joining for N'Ko, Mandaic, Hanifi Rohingya and Mongolian.
  - Replay navigation and zoom persistence.
- **macOS:**
  - Settings and zoom across restart.
  - Reordered copy, search and triple-click, and image rows during bidi
    display.
  - The link pointer, ligature copy, replay navigation and its isolation
    from the shell, and tab moves between windows.

Pending for this release candidate:

- Windows and macOS hands-on checks.
- The Linux manual file-drop check.

Not covered:

- Windows and macOS bidi per-frame cost is unmeasured.
- Execution on the oldest supported Windows build and on ARM64 Windows hosts
  was not tested, for lack of hardware.
- Windows input method editors were not checked.
