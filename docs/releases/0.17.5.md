# OdyTTY v0.17.5

Version 0.17.5 extends bounded text ownership and font shaping beyond the
previous script groups, adds joining scripts and paragraph direction controls,
and corrects image extents, session startup and tab release. Cell addressing,
selection, search, copy, wrapping and reflow retain their logical semantics.

## Text and display

- **General cluster ownership.** Unicode properties extend bounded ownership
  beyond the tuned script groups, including text split across program writes.
  The terminal width profile retains its documented differences from Unicode
  grapheme segmentation. Mode 2027 is permanently set: its query reports set,
  and requests to disable it leave ownership unchanged. The
  [specification](../../SPEC.md#grapheme-cluster-mode-dec-private-mode-2027)
  records the profile and bounds.
- **Font shaping.** With `script_shaping` on, supported multi-scalar owners
  outside the tuned groups also use font shaping. A font must cover the owner;
  missing coverage retains scalar fallback. Shaping stays inside bounded cell
  ownership. An oversized shaped cluster can use a following blank cell,
  without overwriting text there, and the block cursor redraws shaped glyphs
  clipped to its cell. Spacing marks on the scalar fallback path retain their
  cell positions.
- **Joining beyond Arabic.** Syriac, N'Ko, Mandaic, Adlam, Hanifi Rohingya and
  horizontal Mongolian take contextual forms with script shaping enabled.
  Joining requires font coverage; a proportional face can leave gaps between
  letters. Vertical Mongolian and historic joining scripts remain outside the
  supported joining groups. The [shaping reference](../shaping-roadmap.md)
  lists the script and mark boundaries.
- **Updated shaping engine.** `harfrust` 0.14.0 resolves the recorded Bengali
  ka, virama, ra difference from the HarfBuzz reference. This does not imply
  that every font or sequence matches the reference.
- **Paragraph direction and full-screen text.** Opt-in `bidi_reorder` now
  applies on the primary and alternate screens. `bidi_direction` selects left
  to right, right to left or automatic direction in Settings > Rendering and
  the right-click menu. Programs can select paragraph direction with SCP and
  explicit layout with `CSI 8 l`; `CSI 8 h` restores implicit layout. Explicit
  mode and direction persist across screen switches until changed or reset.
  Complex-script owners move as whole spans. Cells, cursor reports, mouse
  reports, selection and copied text stay logical.
- **Images and overlays.** Rows covered by Sixel, Kitty or iTerm2 images keep
  logical order during bidi display. Menus, panels and rename fields retain
  the terminal display map beneath them. Image protocols share the remaining
  scroll-room bound without scrolling to make room.
- **System CJK fallback.** Windows and macOS try installed CJK faces after
  the primary and static chains miss. The fixed order does not infer language
  or regional Han forms from the locale. Missing system coverage still draws
  boxes; disabling symbol fallback disables this lookup.

## Windows, tabs and sessions

- **Windows transparency.** Window transparency now works through DX12
  DirectComposition with a matching window style. The default stays on at 80;
  `window_opacity = 100` keeps the window solid. A failed Visual startup retries
  in an ordinary opaque HWND window. Settings states when the current surface
  cannot be transparent, including other opaque Windows backends.
- **X11 tab release.** A drag preview follows the pointer. Release retires
  that preview and opens an ordinary window around the same session, PTY and
  history. A tiling window manager places the new window; floating managers
  can honor the requested drop position. Escape, return to the source strip
  and preview close cancel the move. Live tab drag can still be disabled in
  Settings > Layout.
- **Ambiguous width at startup.** New sessions apply their width policy
  before terminal output arrives. On Unix, an attached session's host starts
  with the launching window's ambiguous width for Detach & switch, or the
  configured width for `odytty new`. Later setting changes reach only the
  window's mirror: the program's cursor reports keep the host's starting
  width. Windows has no detached session host.
- **Correctness fixes.** Triple-click selection uses the whole logical line
  across soft-wrapped rows. Authorization header redaction accounts for escaped
  values.
  Test temporary directories tolerate spaces and are checked for leftovers.

## Performance and known limits

Bidirectional reordering remains **off by default**. Its measured Linux cost
exceeds the default-on threshold, even with cached plans for unchanged frames.
Windows and macOS per-frame cost is unmeasured. Enabling it remains a live,
optional display choice; the [feature reference](../features.md#ligatures-shaping-and-bidirectional-text)
records the measured Linux ratios and settings.

Measured shaping costs remain recorded costs, not recovered regressions.
The `harfrust` 0.14 comparison found a Devanagari cold frame about 20 percent
slower, from 150 to 181 microseconds, and the parser-only scroll churn row
about 18 percent slower, from 256.7 to 302.9 microseconds; the full-terminal
scroll-region churn row on the same input moved 1.4 percent, which is neutral.
The [memory and performance notes](../memory.md#shaping-engine-comparison)
record this residual and its measurement limits. Other measured changes
reduce selected reflow, shaping, projection and test-device costs; they do not
establish a universal frame-time improvement.

macOS CJK fallback may select the Hong Kong face of the system CJK collection.
Regional glyph selection remains a risk pending macOS hands-on acceptance.
The [feature reference](../features.md) and
[shaping reference](../shaping-roadmap.md#current-support-boundary) describe the
remaining font, script and display limits.

## Platform acceptance
