# OdyTTY v0.15.6

Version 0.15.6 fixes a v0.15.5 regression in which long cursor moves paused
partway through their glide, and makes overflowing right-click menus scroll
predictably.

## Fixes

- **Long cursor moves glide without pausing.** With cursor motion and the
  cursor trail on (the defaults), a cursor jump of more than six cells, such as
  Home or End on a long command line or the return to the prompt after
  multi-line output, started its glide, stopped partway for a fixed interval,
  then snapped to its destination. This came from the v0.15.5 idle-CPU fix: a
  window without splits requested animation frames only for the animations it
  tracked, and the large-jump cursor follower was not among them. The follower
  now requests its own frames, so the glide runs at the normal frame rate from
  start to finish. Split panes, short moves, and the idle-CPU improvement from
  v0.15.5 are unchanged. The missed frame request was on the shared
  single-pane path used on Linux, macOS, and Windows.
- **Overflowing right-click menus.** A right-click menu taller than the window
  now keeps its own scroll position. The mouse wheel and trackpad scroll the
  menu by whole rows, and the highlight stays on the row under the pointer.
  Hovering, or moving the highlight with the arrow keys inside the visible
  rows, does not move the list. On macOS, trackpad travel is accumulated and
  scrolls one row per three cell heights; Linux and Windows scroll one row per
  wheel notch. Menus that fit in the window, settings, the command palette, and
  pickers are unchanged.

## Platform notes and limitations

- **Validation.** Blocking Linux, macOS, and Windows CI passed for each change.
  On device, the uninterrupted long-move glide was checked on Linux (Wayland)
  and macOS, and menu wheel and trackpad scrolling was checked on Linux and
  macOS. Windows is covered by CI only. Idle CPU was not re-measured.
- **Known menu limitations.** The arrow marks on an overflowing menu's border
  are indicators only: clicking them does not scroll the menu yet. Wheel and
  trackpad scrolling can still pause briefly now and then. Both are under
  investigation for a later release.
- **Known Windows issues (also in v0.15.0 and v0.15.5).** With a long, wrapped
  PowerShell prompt, the first typed command can start away from the prompt,
  and Ctrl+Shift+N can insert an `n` and move the cursor of the original
  window. Both are under investigation for a later release.
- **CJK fallback.** With default fonts, Han characters still display as
  missing-glyph boxes, as in v0.15.5; a covering font can be supplied through
  the `symbol_font` setting.
