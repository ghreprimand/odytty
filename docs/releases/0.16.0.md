# OdyTTY v0.16.0

Version 0.16.0 adds pane and window workflows on top of the v0.15.8
behavior: read-only panes, guarded broadcast input, macOS secure keyboard
input, moving tabs and panes between windows, stacked and floating layouts,
scrollback export, an East Asian Ambiguous width preference, a Windows fix
that places the first command after a wrapped PowerShell prompt, and a Windows
fix for a literal letter that Ctrl+Shift+N left in the new window.

## What this release adds

- **Read-only panes.** A per-pane mode, off until toggled from the command
  palette or the terminal menu. There is no default chord
  (`toggle-read-only`). A `READ-ONLY` label stays up (narrow panes show
  `RO`). Keys, IME, paste, drops, and mouse reports do not reach the
  program. Copy, search, scrollback, and resize keep working. Workspace and
  named-layout state keep the flag. One implementation serves Linux (Wayland
  and X11), macOS, and Windows.
- **Broadcast input.** Panes join an in-memory receiver set one at a time.
  The set is never saved. Keys, IME commits, and paste reach every receiver
  as well as the focused pane. A read-only receiver is skipped. A paste that
  contains a line break asks for confirmation and counts receivers, hidden
  panes, and remote panes. `BROADCAST n` and `RECV` labels show the set.
  `Ctrl+Shift+X` empties it and is never sent to a shell. Receivers in other
  windows of the same process are included. Local automation cannot send
  terminal text.
- **Secure keyboard input (macOS).** An explicit process-wide wish, off by
  default, from the command palette or the settings row. There is no default
  chord and no password-prompt detection. `EnableSecureEventInput` runs only
  while the wish is on and an OdyTTY window has keyboard focus. A later
  window adopts the wish already in force. A `SECURE INPUT` label stays on
  each holding window; in a split, stacked, or floating tab it is on the
  focused pane, beside that pane's other labels. A crash while the primitive
  is enabled can leave secure input reported as active, and
  keyboard-intercept tools blocked, until logout (a property of the
  primitive). While secure input is held, hotkey and
  key-remapping apps that use event taps stop working too, including any
  shortcut they provide (for example a remapped quit or window chord),
  exactly as with Terminal.app's Secure Keyboard Entry. Other apps still
  receive keys. Windows and Linux do not
  offer the row or the palette action, and they do not simulate the mode. A
  `secure_keyboard_input` line in a shared config is kept and not applied
  there.
- **Move tabs and panes between windows.** Palette actions and right-click
  menu rows move a tab or the focused pane to a new window or to another
  window through the merge picker. The tab menu's rows act on the right-clicked
  tab, the terminal menu's on the focused pane, and the empty tab-strip menu
  offers Merge This Window Into and Pull Window Into This One when another
  window exists. Merge and pull move complete source workspaces into the
  destination rail; **Move Tab to Window...** adds one tab to its current
  workspace instead. The shell keeps its PTY or attach handle, scrollback,
  images, profile, and `--hold` state. An emptied source window closes and
  hands over the saved-layout role. The quick terminal never sends or
  receives. Dragging a tab or pane out of a window is not supported on any
  platform; the palette actions, the right-click menu rows, and the merge picker
  are the route everywhere. On Wayland the application cannot place the new window, so the
  compositor chooses where it opens.
- **Stacked and floating layouts.** **Stack Panes**, **Float Panes**, and
  **Tile Panes** are palette actions and rows of the terminal right-click menu,
  which shows them in a tab with two or more panes and hides the layout
  already in use. The default stays tiled, and older
  layouts open tiled. Stacked shows the focused pane full-bleed while the
  others keep running. Floating panes are whole-cell rectangles with a
  frame, a z-order, an 8 by 2 cell minimum, and a clamp that never deletes
  a pane. **Arrange Floating Pane** moves and resizes from the keyboard.
  Pointer drag of a floating frame is not implemented. Inline images in a
  floating pane stay hidden while another floating pane covers any part of
  its drawable area, and return when it is uncovered. The bottom-left click
  hint appears only in single-pane tabs. These layouts are
  inside one window, so Linux (Wayland, including Hyprland, and X11),
  macOS, and Windows share one implementation.
- **Scrollback export.** **Export Scrollback As Text** and **Export
  Scrollback As HTML** save the focused pane through the native save dialog;
  the palette and the terminal right-click menu both offer them.
  Text is UTF-8. HTML is one self-contained file with a
  Content-Security-Policy that blocks scripts and network fetches. Only
  `http` and `https` links become anchors. Images are a single `[image]`
  line. Neither format adds application metadata: the working directory,
  host, user, profile, and window title are not written. The terminal text
  itself is exported as it appears, so anything sensitive on screen or in
  scrollback is in the file, and an allowed `http` or `https` link target is
  kept as written. The file shares the command-output writer and the 32 MiB
  cap. Linux uses the XDG portal on Wayland and X11. macOS and Windows use
  their native dialogs.
- **Ambiguous character width.** `ambiguous_width` is `narrow` (default, one
  column) or `wide` (two columns). A pane follows the profile that launched
  it. Changing the value reflows that pane's grid and scrollback. The PTY
  is not resized and the shell is not told. Overlay chrome and the glyph
  atlas stay on the narrow table.
- **Windows first command.** A window's first shells (the launch session, a
  restored layout, and a new window) stay suspended until the window's real
  grid reaches ConPTY, except that a five-second backstop can start a shell
  that no successful resize has released. The window applies the size it
  already has when its surface is created, and a new window is registered
  before that creation.
  Unix spawns are unchanged. A shell whose first resize failed waits for the
  retried resize. Once the window exists, a held shell that no successful
  resize releases starts after five seconds. That start leaves the resize
  retry in place, so a later successful retry can still resize a shell the
  backstop already started, and a first command typed after that resize can
  still land at the old wrapped column. The normal path does not use the
  backstop. A minimized window or repeated resize failures can.
- **Windows new-window chord.** Ctrl+Shift+N, and any other Ctrl+Shift letter
  chord that OdyTTY consumes, no longer leaves its letter in the shell. The
  new window starts with empty modifiers, so the key release, one bare press
  of that letter, or a one-character IME commit that followed the chord was
  encoded as plain text there. Each window now drops at most one such
  leftover, and a different key ends the guard. The new window is registered
  before its surface is created, so its held shell is released at its first
  grid instead of waiting out the five-second backstop. A cursor displacement
  seen after closing the new window did not reproduce once the leaked letter
  was gone, and no separate change addresses it.

## Bounds

Input that cannot be delivered raises an "Input lost" notice. Bracketed
paste is capped at the 8 MiB attach limit before encoding. OSC 52 read
replies over 64 KiB are refused whole. Only the primary window writes the
workspace snapshot. Profile renames and deletes update every window's
bindings. The single-pane image cache is scoped to one session. Session
Navigator and `odytty list` probe hosts without waiting on a stuck peer.
Shell history, desktop entries, images, ssh config, and settings refuse
FIFOs and devices without blocking, and `xdg-mime`, `fc-match`, `fc-list`,
and `wsl.exe` run with a deadline. Profile discovery examines at most 1,024
directory entries and lists at most 256 profiles, and the saved-layout list
examines at most 1,024 entries. Font discovery has its own limits: depth 6,
20,000 collected files, 100,000 examined entries, and 10,000 read
directories. Each truncation is reported. A lost GPU device stays lost.
Bounded scrollback keeps at most 1,024 cells per allowed line on average.

## Packaging

The AppImage now bundles the xkbcommon-x11, Xcursor, and XInput libraries
that the windowing layer loads at runtime; the core `libxkbcommon` stays
host-provided. Earlier AppImages, including the published v0.15.8 one,
panicked at startup on an X11 host without `libxkbcommon-x11`. The release
workflow audits every library name in the shipped binary against the bundled
and host-provided lists, and starts the AppImage under Xvfb in a clean
container that has none of the bundled libraries. The `.deb`,
`.rpm`, and AUR packages declare `libxkbcommon-x11`.
