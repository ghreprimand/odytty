# OdyTTY v0.16.0

These notes describe the v0.16.0 development tree. They are a draft for the
version checkpoint. They are not a published release, and they do not claim
hands-on acceptance.

Version 0.16.0 adds pane and window workflow on top of the published v0.15.8
behavior: read-only panes, guarded broadcast input, macOS secure keyboard
input, moving tabs and panes between windows, stacked and floating layouts,
scrollback export, an East Asian Ambiguous width preference, and a Windows
fix that places the first command after a wrapped PowerShell prompt.

## What this tree adds

- **Read-only panes.** A per-pane mode, off until toggled from the command
  palette or the terminal menu. There is no default chord
  (`toggle-read-only`). A `READ-ONLY` label stays up (narrow panes show
  `RO`). Keys, IME, paste, drops, and mouse reports do not reach the
  program. Copy, search, scrollback, and resize keep working. Workspace and
  named-layout state keep the flag. Linux (Wayland and X11), macOS, and
  Windows behave the same.
- **Broadcast input.** Panes join an in-memory receiver set one at a time.
  The set is never saved. Keys, IME commits, and paste reach every receiver
  as well as the focused pane. A read-only receiver is skipped. A paste that
  contains a line break asks for confirmation and counts receivers, hidden
  panes, and remote panes. `BROADCAST n` and `RECV` labels show the set.
  `Ctrl+Shift+X` empties it and is never sent to a shell. Receivers in other
  windows of the same process are included. Local automation cannot send
  terminal text.
- **Secure keyboard input (macOS).** An explicit process-wide wish, off by
  default, from the command palette or the settings row. There is no default
  chord and no password-prompt detection. `EnableSecureEventInput` runs only
  while the wish is on and an OdyTTY window has keyboard focus. A later
  window adopts the wish already in force. A `SECURE INPUT` label stays on
  each holding window. A crash while the primitive is enabled can leave
  secure input reported as active, and keyboard-intercept tools blocked,
  until logout. While secure input is held, hotkey and key-remapping apps
  that use event taps stop working too, including any shortcut they provide
  (for example a remapped quit or window chord), exactly as with
  Terminal.app's Secure Keyboard Entry. The app's own menu shortcuts are
  unaffected. Other apps still receive keys. Windows and Linux do not
  offer the row or the palette action, and they do not simulate the mode. A
  `secure_keyboard_input` line in a shared config is kept and not applied
  there.
- **Move tabs and panes between windows.** Palette actions move the active
  tab or the focused pane to a new window or to another window through the
  merge picker. The shell keeps its PTY or attach handle, scrollback,
  images, profile, and `--hold` state. An emptied source window closes and
  hands over the saved-layout role. The quick terminal never sends or
  receives. Dragging a tab or pane out of a window is unsupported. On
  Wayland the compositor owns placement and winit reports no drag between
  windows, so the palette is the route there and on X11, macOS, and Windows.
- **Stacked and floating layouts.** **Stack Panes**, **Float Panes**, and
  **Tile Panes** are palette actions. The default stays tiled, and older
  layouts open tiled. Stacked shows the focused pane full-bleed while the
  others keep running. Floating panes are whole-cell rectangles with a
  frame, a z-order, an 8 by 2 cell minimum, and a clamp that never deletes
  a pane. **Arrange Floating Pane** moves and resizes from the keyboard.
  Pointer drag of a floating frame is not implemented. Inline images in a
  floating pane stay hidden while another floating pane covers any part of
  its drawable area, and return when it is uncovered. These layouts are
  inside one window, so Linux (Wayland, including Hyprland, and X11),
  macOS, and Windows share one path.
- **Scrollback export.** **Export Scrollback As Text** and **Export
  Scrollback As HTML** save the focused pane through the native save dialog.
  Text is UTF-8. HTML is one self-contained file with a
  Content-Security-Policy that blocks scripts and network fetches. Only
  `http` and `https` links become anchors. Images are a single `[image]`
  line. Neither format carries the working directory, host, user, profile,
  or window title. The file shares the command-output writer and the 32 MiB
  cap. Linux uses the XDG portal on Wayland and X11. macOS and Windows use
  their native dialogs.
- **Ambiguous character width.** `ambiguous_width` is `narrow` (default, one
  column) or `wide` (two columns). A pane follows the profile that launched
  it. Changing the value reflows that pane's grid and scrollback. The PTY
  is not resized and the shell is not told. Overlay chrome and the glyph
  atlas stay on the narrow table.
- **Windows first command.** A window's first shells (the launch session, a
  restored layout, and a new window) stay suspended until the window's real
  grid reaches ConPTY. The window applies the size it already has when its
  surface is created, and a new window is registered before that creation.
  Unix spawns are unchanged. A shell whose first resize failed waits for the
  retried resize. Once the window exists, a held shell that no successful
  resize releases starts after five seconds. That start leaves the resize
  retry in place, so a later successful retry can still resize a shell the
  backstop already started.

## Bounds landed with this tree

Input that cannot be delivered raises an "Input lost" notice. Bracketed
paste is capped at the 8 MiB attach limit before encoding. OSC 52 read
replies over 64 KiB are refused whole. Only the primary window writes the
workspace snapshot. Profile renames and deletes update every window's
bindings. The single-pane image cache is scoped to one session. Session
Navigator and `odytty list` probe hosts without waiting on a stuck peer.
Shell history, desktop entries, images, ssh config, and settings refuse
FIFOs and devices without blocking, and `xdg-mime`, `fc-match`, `fc-list`,
and `wsl.exe` run with a deadline. Profile and font discovery each stop at
1,024 entries and say so. A lost GPU device stays lost. Bounded scrollback
keeps at most 1,024 cells per allowed line on average.

## Device acceptance still open

The items below are implemented in this tree. This block records that
hands-on acceptance is still open. It is not a claim that any of them
passed on a device, and it can be removed or replaced when those results
exist.

- Read-only panes on Linux, macOS, and Windows.
- Broadcast input on Linux, macOS, and Windows.
- Secure keyboard input on macOS (toggle, label, and focus release against
  the session secure-input owner). Linux and Windows: the settings row and
  the palette action are absent.
- Stacked and floating layouts on Linux (Wayland and Hyprland), macOS, and
  Windows, including keyboard arrange and the covered-image limit.
- Moving tabs and panes on Linux (Wayland), plus NVIDIA window
  create/destroy, macOS, and Windows.
- Scrollback export as text and HTML, opened in a browser, on Linux, macOS,
  and Windows.
- Windows: a long wrapped PowerShell prompt at startup and in a new window
  places the first typed command directly after the prompt.
- Ambiguous width on Linux. The v0.16.0 TODO section has no separate device
  line for it.
